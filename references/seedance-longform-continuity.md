# Seedance 高約束多鏡頭一致性編譯器

將長篇自然語言需求編譯成 Seedance 可執行的「參考素材綁定 + 狀態鎖 + 時間碼 + 事件狀態機 + 驗收契約」。適用於參考圖角色、多鏡頭敘事、時間凍結／倒轉、複雜物理、年代場景及 15 秒以上故事。

## 1. 證據狀態與版本邊界

本方法萃取自使用者提供、標示為「Seedance 2.0／2.5」的 30 秒高約束提示詞樣本。把它視為**實戰樣本**，不是官方語法規格。

截至 2026-08 可由 ByteDance／BytePlus 官方公開文件確認的 Seedance 2.0 能力：

- 文字、圖片、音訊、影片四種輸入模態
- 最多 9 張圖片、3 段影片、3 段音訊的混合參考
- 15 秒高品質多鏡頭音影片輸出
- 加強複雜互動、物理準確度、指令遵循、一致性、延長與編輯

官方來源：<https://seed.bytedance.com/blog/seedance-2-0-official-launch>

BytePlus 已有 **Seedance 2.5 official launch** 頁，可確認名稱／上線行銷：<https://www.byteplus.com/en/contact-us/ai-seedance2-5-official>。但截至研究日，公開 ModelArk prompt guide／API 詳細限制仍主要列 2.0。**不要把 30 秒、4K、50 references 或局部編輯寫成所有 2.5 入口的共同保證。** 先做 [seedance-2-5-community-playbook.md](seedance-2-5-community-playbook.md) 的 capability gate；未通過就按實際時長與素材槽位降級。

### 時長路由

- **2.0：** 以 15 秒為單次硬邊界。30 秒故事拆成 2–3 段，使用上一段尾幀／影片延長接續。
- **後續版本且 UI 明確支援 30 秒：** 可單次生成；仍以 3–5 個主要事件節點為佳。
- **不確定版本：** 不假設 30 秒。先寫可切段的 beat sheet，再決定一次生成或續接。

## 2. 樣本萃取出的八層架構

| 層 | 功能 | 寫法 |
|---|---|---|
| 1. Reference Binding | 指定每個素材的唯一職責 | `圖一只負責主角身份；不要用文字重畫臉` |
| 2. Deferred Binding | 允許首鏡自由建立未指定變數 | `服裝可自由建立；第一鏡確立後全片鎖定` |
| 3. Invariant Ledger | 列出跨鏡不可變項 | 身份、服裝、身形、髮飾、杯子、吸管、配角、場景位置 |
| 4. World Bible | 鎖年代、地域、材質、光線與禁入元素 | 具體道具與建材優於只寫「復古」 |
| 5. Beat Sheet | 用時間碼分配每鏡唯一主任務 | `[0–4s｜中廣角]` + 可視動詞 + 結束狀態 |
| 6. Event State Machine | 把複雜事件拆成狀態轉換 | 正常 → 碰撞 → 凍結 → 環繞 → 倒轉 → 恢復 |
| 7. Physics Ledger | 區分材質、重量、軌跡與時間規則 | 茶、醬料、玻璃、金屬、食物分別描述 |
| 8. Acceptance Contract | 把不可接受結果分類 | 身份、物理、年代、鏡頭、文字、解剖、結尾 |

## 3. 關鍵設計模式

### 3.1 參考圖只綁身份，不重述外貌

參考圖已提供臉部資訊時，避免再用文字描述五官、臉型、膚色或年齡，否則文字與圖像可能競爭。使用：

```text
【圖一】是主角唯一身份與外貌來源。直接沿用圖一，不用文字重新設計外貌。
```

若平台支援資產標記，將「圖一」替換成實際標記，例如 `@HeroReference`。

### 3.2 Deferred Binding：先自由建立，再永久鎖定

對使用者不在意、但跨鏡必須一致的變數，使用兩階段約束：

```text
服裝與身形可由第一鏡依年代場景自然建立；第一鏡一旦確立，後續所有鏡頭完全沿用，不得重新設計。
```

這不是矛盾，而是「首鏡初始化 → 後續唯讀」。適合服裝、配件細節、身形比例、妝容與未指定道具。

### 3.3 Signature Anchor：用一個高辨識元素補強身份

選一個容易跨鏡辨認的元素，例如髮圈、胸針、圍巾或手錶，固定：

- 名稱：所有鏡頭使用同一字串
- 顏色、材質、尺寸、位置
- 禁止替代形態
- 在關鍵鏡頭保持可見

不要每鏡改同義詞。`米白色寬版布質髮圈` 後面不可改寫成 `奶油色頭帶`。

### 3.4 Anchor-Noun Registry：同物同名

在寫分鏡前建立詞彙登記表：

```text
主角：主角
身份錨：米白色寬版布質髮圈
主道具：透明玻璃杯裝珍珠奶茶
飲用工具：粗吸管
服務生道具：不鏽鋼托盤、透明玻璃紅茶壺
```

後續逐字沿用，不用修辭性同義替換。這比反覆寫「保持一致」更有效。

### 3.5 Event State Machine：複雜特效要寫狀態，不只寫畫面

```text
S0 正常：所有人物與物件正常時間流動。
S1 碰撞：托盤與液體依真實動量離手。
S2 凍結：到達最高點後，除主角外全部位置與形變固定。
S3 例外：主角、主角手中杯子與吸管維持正常時間。
S4 倒轉：凍結物件沿原軌跡逆向，不新增、不穿透、不跳格。
S5 復位：每件物品回到 S0 的唯一原始位置。
```

每次狀態轉換都寫清楚：**觸發條件、受影響集合、例外集合、結束條件**。

### 3.6 Exception Mask：誰不受全局效果影響

只寫「時間凍結，主角能動」不夠。要把主角攜帶物一起列入例外，否則人物能動、杯子卻凍住：

```text
正常時間集合：主角、主角頭髮、髮圈、手、玻璃杯、杯內奶茶、冰塊、黑珍珠、粗吸管。
凍結／倒轉集合：其他人物、空中食物、餐具、托盤、紅茶與醬料。
```

### 3.7 Physics Ledger：不同材質不可共用同一物理描述

至少區分：

- 稀液體：透明度、折射、表面張力、細滴與飛行軌跡
- 稠液體：黏度、拉絲、較慢變形
- 固體食物：重量、慣性、旋轉速度
- 玻璃／瓷器／金屬：剛性、反射、不可軟化或穿透
- 凍結狀態：完全清晰、無運動模糊、無形變
- 倒轉狀態：嚴格沿原軌跡，數量守恆

### 3.8 Deliberate Anachronism：年代衝突要明示

若場景年代與英雄道具刻意不相容，不要讓模型自行解決矛盾。標記：

```text
這是刻意的單一時代錯置：英雄道具是全片唯一允許的非該年代元素；其餘服裝、建築、車輛與道具嚴格符合年代。
```

若不是刻意，就替換掉衝突元素。

## 4. 編譯流程

1. **解析輸入角色**：每張圖／影片／音訊只指定一個主要職責。
2. **建立不變量帳本**：身份、服裝、配件、道具、場景、空間站位。
3. **建立錨點詞彙表**：同一物件只用一個名稱。
4. **畫事件圖**：列 S0→S1→S2…，標記觸發、集合、例外與復位條件。
5. **做時長預算**：每個 beat 只留一個主任務；複雜物理至少給 3–5 秒。
6. **寫時間碼分鏡**：每段包含景別、單一主運鏡、主任務、表演、結束狀態。
7. **補物理帳本**：只描述故事真的需要的材質差異。
8. **補驗收契約**：按類別列禁令，不把所有 `禁止` 混成一段。
9. **做版本路由**：2.0 超過 15 秒就切段；續接時帶尾幀、狀態膠囊與不變量帳本。
10. **刪除低訊號重複**：每項核心限制最多出現在全局、關鍵鏡頭、最終驗收三處。

### 續接用 State Capsule

每段結尾輸出一份續接摘要，下一段原樣帶入：

```text
[Continuation State]
Time state: <正常／凍結／倒轉中>
Hero state: <姿勢、視線、手勢、杯子位置>
World state: <人物與物件位置>
Unresolved motion: <下一段必須延續的軌跡>
Locked invariants: <身份、服裝、錨點、道具、光線、空間>
```

## 5. 可直接套用的模板

```text
[Model / Duration]
Seedance <實際可用版本>，<時長>，<畫面比例>。

[Reference Roles]
【圖一】只作為主角唯一身份與外貌來源；直接沿用，不用文字重畫外貌。
<其他素材及各自唯一職責>

[Priority]
身份一致 > 狀態連續 > 事件因果 > 物理可信 > 鏡頭 > 風格細節。

[Deferred Bindings]
<第一鏡可自由建立的變數>；第一鏡確立後全片唯讀，不得重設。

[Invariant Ledger]
- 主角：<身份來源與不可變項>
- Signature anchor：<固定名稱、顏色、材質、尺寸、位置>
- Hero prop：<固定名稱與狀態>
- Supporting cast：<外貌／服裝／位置>
- Environment：<空間拓撲與光線>

[World Bible]
<年代、地域、建材、家具、窗外、服裝、光線、色彩、質感>
<如有刻意時代錯置，在此指定唯一例外>

[Anchor-Noun Registry]
<角色與道具：唯一固定名稱>

[Event State Machine]
S0 <正常狀態>
S1 <觸發事件>
S2 <特殊狀態>
S3 <例外集合>
S4 <逆轉／恢復規則>
S5 <完成條件>

[Timeline]
[00:00–00:04｜中廣角]
Camera: <一個主運鏡>
Action: <一個主任務>
Performance: <克制、可視化動作>
End state: <下一鏡必須接住的狀態>

[00:04–00:08｜動態追蹤]
Camera: ...
Action: ...
Physics: ...
End state: ...

<依時長續寫；每段只留一個主任務>

[Physics Ledger]
- <材質 A>：<透明度／黏度／重量／折射／表面張力>
- <材質 B>：<與 A 明確不同的行為>
- Motion blur：只出現在真正移動的物件。
- Conservation：不複製、不消失、不穿透；倒轉沿原軌跡。

[Audio]
<環境音／SFX／配樂／對白；無對白就明寫 no dialogue, no lip speech>

[Acceptance Contract]
Identity: <不可變臉、不可改齡、不可換裝...>
Continuity: <道具、站位、光線、空間連續>
Physics: <不可跳格、瞬移、複製、穿透、液體同質化>
Camera: <不可分割畫面、不可無故硬斷>
Typography: no text, subtitles, logo, watermark, UI.
Ending: <最後一幀與禁止淡出／黑畫面>
```

## 6. 壓縮與優先級規則

### 保留

- 參考素材角色分工
- Deferred binding 與第一鏡鎖定
- 不變量帳本與固定錨點字串
- 時間碼、每段主任務與結束狀態
- 狀態機、例外集合、復位條件
- 材質差異與數量守恆
- 分類驗收契約

### 壓縮

- 場景陳設只留 6–10 個辨識度最高元素
- 同一限制最多重申三次：全局、風險鏡頭、最終驗收
- 同義 negative 合併，例如 `變形／重設計／漂移` 不必散落十次
- 純風格形容詞讓位給空間、動作、狀態與因果

### 優先級

```text
P0 身份與安全邊界
P1 狀態連續與因果
P2 物理與數量守恆
P3 鏡頭與表演
P4 美術、光線與質感
P5 裝飾細節
```

遇到 token／指令容量不足時，從 P5 往上刪，不能先刪 P0–P2。

## 7. 常見失敗與修法

| 失敗 | 根因 | 修法 |
|---|---|---|
| 角色跨鏡變臉 | 參考圖與文字外貌互相競爭 | 參考圖只綁身份；刪除重畫臉的描述 |
| 首鏡服裝後續漂移 | 自由變數沒有轉為唯讀 | 加 Deferred Binding + Invariant Ledger |
| 髮飾消失或變款 | 只寫「戴髮飾」，沒有固定屬性 | 固定名稱、材質、色彩、寬度、位置與禁用替代形態 |
| 凍結時主角杯子不動 | 例外集合只列人物 | 把主角攜帶物、頭髮與衣物一起列入正常時間集合 |
| 倒轉時物件複製 | 沒有唯一來源與數量守恆 | 寫原軌跡回溯、唯一原位、不新增、不穿透 |
| 所有液體像同一種果凍 | 沒有材質分流 | 分別指定透明度、黏度、重量、折射與表面張力 |
| 360° 環繞不完整 | 同時塞入凍結、表演、倒轉等多個主任務 | 環繞獨立成 beat；必要時跨片段續接 |
| 年代場景被現代化 | 正面場景詞弱於現代英雄道具 | 標明唯一時代錯置；其餘年代元素列為硬約束 |
| 無對白卻出現說話口型 | 只寫「沒有台詞」 | 加 `no dialogue, no lip speech, mouth moves only for the specified physical action` |
| 30 秒在 2.0 被截斷 | 超過官方 15 秒單次能力 | 拆 2–3 段，使用尾幀／延長與 State Capsule |

## 8. 交付前驗收

- [ ] 每個參考素材只有一個主要職責
- [ ] 參考人物未被文字重新設計外貌
- [ ] 自由變數有「第一鏡建立後鎖定」規則
- [ ] 所有跨鏡物件使用相同 anchor noun
- [ ] 每段只有一個主任務與一個主要運鏡
- [ ] 複雜事件已寫成狀態轉換與例外集合
- [ ] 所有飛散物有唯一來源、原軌跡與復位位置
- [ ] 不同材質有不同物理參數
- [ ] 年代衝突已消除或標明唯一刻意例外
- [ ] 2.0 超過 15 秒已拆段並附 State Capsule
- [ ] Negative 已分類且只保留故事相關項目
- [ ] 結尾是可驗證的畫面狀態，不用抽象情緒代替
